# AI Budget Report Analyst

A Streamlit application that ingests a budget spreadsheet, analyses it, visualises
it, and generates an executive summary with the Claude API.

Built for a university class project demonstrating generative AI applied to
financial budget analysis.

## Tech stack

| Tool | Role |
| --- | --- |
| Python 3.9+ | Language |
| Streamlit | Web interface |
| pandas | Data manipulation |
| openpyxl | Excel file reading |
| Plotly | Interactive charts |
| Claude API | AI executive summary *(Milestone 5)* |

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Sample data (for the tests)

```bash
python scripts/generate_sample_budget.py
```

Regenerates `sample_data/sample_budget.xlsx`, which the test suite runs
against. The app itself only accepts uploads — there is no sample-file option
in the UI.

## Run

```bash
streamlit run app.py
```

Then open http://localhost:8501 in a browser.

## Run the tests

```bash
python tests/test_analyzer.py
python tests/test_charts.py
python tests/test_ai_chat.py
python tests/test_app_smoke.py
```

The first three test the analysis engine, the chart builders and the AI layer in
isolation. The fourth runs the whole Streamlit app headlessly with Streamlit's
`AppTest` harness. **None of them need an API key or network access** — the
Anthropic client is replaced with a test double.

## Deploying to Streamlit Community Cloud

Streamlit Cloud builds directly from the GitHub repository, so deployment is
configuration rather than a build step.

1. Push this repository to GitHub.
2. Sign in at [share.streamlit.io](https://share.streamlit.io) with the same
   GitHub account and authorise it to read the repository.
3. **Create app** → **Deploy a public app from GitHub**, then set:
   - Repository: your repo
   - Branch: `main`
   - Main file path: `app.py`
   - Advanced settings → Python version: **3.11** or newer
4. Deploy. The first build installs `requirements.txt` and takes a few minutes.
5. Paste the resulting URL into the **Live app** line at the top of this file.

### Secrets (from Milestone 5 onward)

The Claude API key must **never** be committed. `.gitignore` already excludes
`.env` and `.streamlit/secrets.toml`. On Streamlit Cloud, add it under
**App settings → Secrets** instead:

```toml
ANTHROPIC_API_KEY = "sk-ant-..."
```

## Conventions

**Variance = actual − budgeted.** A *positive* variance means **over budget**.
This is the standard convention for expense budgets, where spending more than
planned is what you want flagged.

**The 3% flag.** Anything more than 3% over budget is marked 🔴; everything
else 🟢. The threshold is a percentage rather than an amount, so a $3,000
overspend on a $10,000 budget is flagged while the same $3,000 on a $2,000,000
budget is not — percentage is what tells you an area is out of control. Change
it in the sidebar.

Under-budget lines are never flagged red. That is a different question with a
different answer, and colouring it red would train the reader to ignore red.

## What your spreadsheet needs

Three things, in any column order and under any column names:

1. A **label** column — department, category, or account name
2. A **budgeted amount** column
3. An **actual amount** column

Amounts may be plain numbers or text (`$1,200.00`, `(500)`, `1.200,50`). TOTAL
and SUBTOTAL rows are detected and excluded. Optional department, category and
period columns unlock the grouped breakdowns and the trend chart. Everything
the app detects is shown in the sidebar for you to correct.

## How the AI works

Claude is sent the **analysed figures**, never the raw spreadsheet: totals,
per-department and per-category breakdowns, the largest variances, and the data
quality notes. pandas does the arithmetic; Claude does the explaining.

That split is deliberate. Language models are unreliable at arithmetic and
excellent at explanation, so every number in an answer traces back to a figure
computed in `analyzer.py` — the same figure shown on the Report tab.

The system prompt forbids inventing causes. The spreadsheet records *what*
happened, not *why*, so when asked "why did payroll exceed budget?" Claude says
the data cannot answer that, then gives what the numbers do support and labels
any suggested cause as a hypothesis to check.

Two features use Claude — the executive summary and the chat — and they share
one API path in `ai_client.stream_text()`. Each supplies its own instructions;
the client owns the model settings, the fallback handling, and error messages.

### The baseline comparison

`analyzer.headline_sentence()` writes the same verdict from an if-statement, at
no cost and with no API. The app shows both side by side, because the
comparison is the point: use AI where judgement about *relevance* is needed —
which departments to name, which variances matter, what to investigate — and a
formula where a formula already works.
